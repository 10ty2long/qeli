## Исправленные замечания

**Q14-F026, P2 — ошибка проверки DNS-правила считалась успешной очисткой.**
Прежний `delete_exact_rule` использовал bool `rule_present`. Отказ запуска и любой
ненулевой статус `-C` превращались в «правила нет», после чего cleanup возвращал успех.
Кроме того, удаление ровно 1024 копий заканчивалось ошибкой лимита без последней проверки.
Теперь ошибка проверки остаётся ошибкой, а после последнего разрешённого удаления
выполняется ещё один `-C`. Оставшееся правило, включая успешный no-op, даёт отказ.

**Q25-F018, P2 — проверка kill-switch принимала общие ошибки за отсутствие.**
`absent_check` принимал любой exit code 1, а сообщения об отсутствии — независимо
от кода выхода. При stderr с отказом доступа клиент мог подтвердить отсутствие
непроверенной цепочки. Код 1 не является исключительно признаком отсутствия правила:
его используют и другие ошибки — см. [руководство Netfilter, DIAGNOSTICS](https://ipset.netfilter.org/iptables.man.html).
Это дефект подтверждения очистки; фактическая утечка трафика на Linux здесь не проверялась.

**Q25-F019, P2 — сообщение о другой цепочке могло подтвердить отсутствие своей.**
Имя искалось как подстрока после перевода всего сообщения в нижний регистр. Поэтому
`QELI_KS_edge2` и `QELI_KS_Edge` могли совпасть с ожидаемым `QELI_KS_edge`.
Теперь имя между кавычками сравнивается целиком с учётом регистра.

## Общая реализация и совместимость

`qeli/src/firewall_check.rs` разбирает результат команды для server NAT и проверяемых
Linux kill-switch операций. Прежняя отдельная реализация `absent_check` удалена;
разбор ошибок теперь один. Он возвращает present / absent / ошибку неизвестного состояния.
Обычные bool-проверки установки правил остаются прежними: их контракт иной, все их
call sites ещё требуют отдельного аудита.

Для `-C` сохранён прежний контракт silent miss: код 1 с пустым stderr принимается как
отсутствие. Это допущение совместимости для штатного инструмента/обёртки; оно не позволяет
различить произвольную неисправную обёртку с таким же результатом. Для неудачного `-S`
пустой stderr уже не подтверждает отсутствие. Известные сообщения об отсутствии правила
принимаются с кодом 1. Missing-target/chain с кодом 1 или 2 принимается только для точного
ожидаемого имени цепочки; поддержаны кавычки legacy/nft и стандартная строка помощи.
Неизвестные сообщения, дополнительные ошибки и другие коды не означают отсутствие.

Алгоритм точечного удаления перенесён в `qeli/src/server/nat/cleanup.rs`; отдельный
серверный цикл удалён. `cleanup_dns_input_with` передаёт ему оба правила: UDP и TCP.
Отказ одной ветви не пропускает вторую; диагностика содержит обе причины. Команды
проверки и удаления получают одинаковые table/chain и полный rule spec, включая tag,
интерфейс, адреса, порт и протокол. Общий `-S` не требуется: путь mixed native nft
с недоступным listing сохраняется. Максимум — 1024 удаления на одно правило.

INI, manual/route/nat66/off, ABI и клиентские приложения не меняются. Модуль используется
Linux-кодом сервера/клиента и host-тестами; это не новая реализация Windows/macOS firewall.
DNS lease, supervisor, порядок завершения и запуск системных процессов не переработаны.

## Открытые границы

Q14-F027 остаётся открытым: DNS lease пишет ошибку из Drop, но не передаёт её итоговому
статусу остановки worker. Следующий этап — проверяемый explicit cleanup и отдельная
интеграция передачи ошибок с учётом native nft; весь lifecycle здесь не объявлен исправленным.
NAT/kill-switch пока используют прежние процессы без общего deadline. Проверка/удаление
не атомарны относительно внешнего администратора. Реальные backend/version/locale
комбинации требуют целевого Linux: неизвестное сообщение возвращает ошибку проверки.
Linux runtime, реальные firewall/TUN/DNS, устройства, native release-сборки,
SSH/systemd/Actions и бенчмарки не запускались.

Предыдущий этап: [конечный NAT sweep](AUDIT-Q14-NAT-CLEANUP.md).

Продолжение: [Q14-F028](AUDIT-Q14-DNS-OWNERSHIP.md) сохраняет точное владение после
неудачного Drop/rollback в памяти worker и добавляет retry. Q14-F027 и восстановление
после перезапуска остаются открытыми.
