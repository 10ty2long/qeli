# Q29: восстановление Android VPN после смерти процесса

13 октября 2026 года в Qeli добавлена закрытая служба `VpnRecoveryService` в том же процессе. Android может перезапустить её с пустым intent, после чего она один раз запрашивает восстановление у основной VPN-службы. Проверяются сохранённое желание подключаться и действующее VPN-разрешение. Основная служба использует зашифрованный снимок INI текущего соединения и игнорирует повторный callback, если контроллер уже работает. Выбор профиля в интерфейсе не определяет конфигурацию этого восстановления.

Снимок хранится через существующий AES-GCM/Android Keystore, отдельно от списка профилей; пароль не добавляется в обычные preferences или restart intent. Ошибка сохранения запрещает новый запуск/переконфигурацию. Disconnect и onRevoke останавливают запись восстановления и удаляют снимок. Обе службы используют одно существующее уведомление с кнопкой Disconnect. Таймеров, фонового опроса, BPF и изменения системного lockdown нет.

Проверены 201 JVM-тест, lint без Error/Fatal, release R8, обе неизменные JNI-библиотеки, вывод анализатора API instrumentation. В Android14/API34 x86_64 прошли пять целевых Android-тестов manifest/зашифрованного снимка. Затем тестовое приложение удалено; аутентификация и сетевые проверки выполнены на обычном production R8 APK, подписанном лабораторным сертификатом. Все исходные ZIP-элементы APK неизменны; добавлены только стандартные элементы подписи. Настоящая release-подпись этим не проверяется.

| Проверка | Результат |
| --- | --- |
| SIGKILL настоящего Qeli | Новый PID 2202 → 3107, аутентифицированный NetworkPlan за 2.99 с; одна новая VPN-генерация |
| Отдельное приложение после восстановления | Ответ и хеш полезной нагрузки подтверждены сервером из VPN-подсети |
| UI Disconnect и повторный Connect | 30 с без возврата обеих служб; lockdown блокирует трафик; после подключения TCP/UDP IPv4/IPv6 PASS |
| Force-stop | 30 с без самозапуска, трафик заблокирован; ручное восстановление PASS |
| Отзыв разрешения через Android Settings | desired=false, обе службы/TUN отсутствуют после 30 с |
| Лаба | Сервис хоста и исходные AVD-данные сохранены; весь собственный runtime-root архивирован и удалён |

Это проверка одного API34 стенда и ограниченных окон наблюдения, не гарантия сроков перезапуска на всех Android/OEM. Два предыдущих неудачных прототипа и исторический отказ штатного redelivery сохранены. Успешный отдельный Java-прототип (2.64/1.86 с) квалифицирован отдельно; таблица выше относится к настоящему Qeli.

Q29 остаётся IN_PROGRESS: обход generic/null DnsResolver ENONET для чужих приложений не найден и пользователем не принят как ограничение. `allowBypass` не включён. Физические платформы, полный аудит, hosted CI и публикация не квалифицированы. План: 33/37 (89.2%). NO_PUSH_DEPLOY_RELEASE.
