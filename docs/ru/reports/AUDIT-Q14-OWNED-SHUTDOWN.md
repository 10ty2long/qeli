# Q14: итоговая проверка DNS и IPv6 sysctl при остановке worker

Дата: 23 сентября 2026. Исходный коммит: `44f19ce8`.
Разделы 14, 17, 18 и 19: **IN_PROGRESS**. Q14-F027 исправлена **частично**.

## Подтверждённая проблема

После Q14-F028 точные DNS rule specs переживали неудачный Drop, а IPv6 sysctl leases
уже сохранялись при отказе восстановления. Но остановка worker завершалась с кодом 0
по сигналу, если успешно сохранялась статистика. Ошибки ресурсов оставались в логах;
строка `Server shutdown complete` появлялась даже при неудачном сохранении статистики.
При одновременных сбоях worker и flush возвращаемая ошибка сохраняла только первую причину.

## Изменение

После завершения profile supervisors, обычных tag sweeps и post_down выполняется
`nat::finish_owned_cleanup()`. Под общим firewall mutex он повторяет очистку всех
ожидающих DNS записей и освобождение всех IPv6 sysctl leases, оставшихся в реестре
текущего worker. Отказ DNS не отменяет sysctl cleanup; отказ одного профиля не пропускает
остальные. Неудачная очистка сохраняет ownership для retry, успешная удаляет запись.

DNS registry дополнительно проверяет активные leases: после завершения профилей их
не должно быть. Такой lease даёт ошибку `DNS INPUT lease still active at worker shutdown`;
его правила не удаляются этой проверкой. Это обнаруживает незавершённое владение без
предположения, что активная запись уже никому не нужна.

`qeli/src/server/shutdown.rs` объединяет исходную причину остановки worker, итоговую
ошибку известных сетевых ресурсов и ошибку usage flush. Сохраняется каждая категория,
размер её текста ограничен 2048 символами. Статистика сохраняется и после ошибки сети;
эксклюзивный control socket lease удерживается до этой попытки.

При остановке по SIGINT/SIGTERM worker возвращает код 1, если итоговый результат ошибочен.
При завершении без сигнала возвращается тот же Result. `Server shutdown complete`
выводится только для успешного результата, иначе — `Server shutdown failed: ...`.
Ранее зарегистрированный временный отказ сам по себе не делает остановку ошибочной,
если окончательный retry подтвердил освобождение ресурса. Предыдущие ошибки остаются
в журнале, но не являются «липким» флагом отказа.

Проверка намеренно ограничена **известными текущему worker владельцами**. Generic NAT
sweep сохраняет прежнее поведение: недоступность `iptables-nft -S` на mixed native nft
не превращена в безусловный отказ запуска. Новых INI-параметров нет; ABI и wire format прежние.

## Проверка

14 новых host-тестов: четыре DNS registry, четыре orchestration и шесть итогового
результата worker. Проверены активные/ожидающие записи, постоянный отказ и успешный
retry, сохранение specs, продолжение очистки после отказов, все категории ошибок и
ограничение диагностики.

**971 host unit + 52 editor/policy + 7 examples + 12 server INI = 1042 Rust tests PASS.**
Linux all-targets Clippy, client-only, client без roaming, server-only, minimal FFI,
compatibility без features и rustfmt PASS. Прежние feature-specific warnings сохранены;
Clippy использует прежнее исключение chunks_exact_to_as_chunks для ndp_proxy.

Дополнительно: восемь сценариев отдельных host-процессов с извлечённым production tail
`run_worker`, настоящим `process::exit`, production NAT adapters и portable registry.
Firewall/sysctl, статистика и control lease заменены фикстурами; реальный Linux worker

## Что осталось открытым

Q14-F027 **не закрыта**: ошибки generic NAT sweep, удаления TUN, таймауты/паники очередей
и результаты JoinSet при shutdown ещё не проходят через полноценный общий результат.
Успех новой проверки не подтверждает эти ресурсы. Выход worker также не является
доказательством корректного отображения результата внешним supervisor/systemd.

Проверяются только leases в памяти worker. Неудачный частичный acquire до регистрации
IPv6 lease, записи старого worker и IPv4 forwarding, удерживаемый на время жизни worker,
не покрываются новым проходом как отдельные классы владения. `sysctl::recover()` всё ещё
может вернуть Ok после сохранения неустранённых stale entries; его контракт требует
отдельного прохода. DNS registry не переживает crash/restart, persistent journal отсутствует.

Firewall-команды не имеют общего deadline; зависшая команда может задержать и финальную
проверку. Linux runtime, реальные firewall/TUN/DNS, устройства, native release,
SSH/systemd/Actions и бенчмарки не запускались.
